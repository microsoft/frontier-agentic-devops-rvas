What the wizard does

Use it when you want to configure a workspace without working through each setup activity by hand. It supports GitHub Enterprise Cloud on github.com and your enterprise's ghe.com domain.

  • Workspace: create organizations under an existing enterprise, or explicitly adopt existing ones. Set up teams and repositories with Node.js, Python, or your own templates.
  • Delivery controls: configure supported Actions policies and review rules. Add CI and Codespaces configuration where selected.
  • Copilot and security: prepare shared instructions and agents, assign selected Copilot seats when prerequisites are met, and configure supported Code Security and Code Quality settings.
  • Other capabilities: select inventory reports or supported operations for migration, integrations, and repository governance. The plan names work that needs an owner or an external system.

Workspace, Actions with Codespaces, Code Security, and Code Quality start selected. You can change the selection. Required packages are included automatically.

For a new project, the defaults include a Developers team and a service repository with a Node.js starter and CI. Existing-resource adoption is explicit. Repository content changes go through pull requests; new repositories receive their approved initial content directly.

What stays manual

The enterprise account must already exist. Any required SSO and SCIM setup must already be complete; the wizard does not inspect it or create handoffs for it. The script also leaves cloud-side OIDC trust and runner compute to your team.

The wizard does not deploy Azure infrastructure or provision the curriculum's sample applications.

Some licensing and policy settings need an owner in GitHub settings. Those steps remain tracked handoffs. Selecting migration or SRE capabilities does not complete a migration or deploy Azure SRE Agent.

And you can still use the hands-on sessions to understand a control, complete manual work, or test the result with your team. The session builder selects learning activities; it does not configure GitHub.

Review before anything changes

The interview saves a configuration file. doctor checks prerequisites, and plan produces the proposed operations and file contents. GitHub changes start only when you approve and apply the saved plan.

Approval includes selected purchases and live workflow runs. They can incur costs. Read the billing warnings and recipients in the plan; apply has no separate cost confirmation.

A run records each action so you can resume it and verify the result. Pending handoffs and unverified actions remain visible. Keep configuration files and run reports outside source control.
