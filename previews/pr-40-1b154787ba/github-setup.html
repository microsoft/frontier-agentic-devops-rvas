Set up or align an enterprise

Use the skill for coordinated changes across an existing GitHub Enterprise Cloud account on github.com or your enterprise's ghe.com host.

Describe the outcome in your own words. For example, align organization governance, set up teams and repository access, or roll out Copilot. The skill narrows the work to that outcome.

  • Organization and access: plan landing zones, identity requirements, and team access.
  • Repositories and delivery: plan repository factories, rulesets, and Actions policies.
  • Security and Copilot: assess rollout needs, settings, and licensing effects.
  • Governance: trace effective policy to its source and track work that needs another owner.

One prompt starts the guided workflow. Plan includes read-only discovery and prioritized recommendations. The agent asks only for unresolved decisions, one at a time.

Required read-only inventories within your requested scope do not need another skill-level approval. Copilot's tool permissions and your organization's policies still apply.

Before you start

You need GitHub Copilot CLI installed and signed in, GitHub CLI (gh), and jq. Authenticate gh to the intended host with an account that can inspect the selected resources. Changes may require an enterprise or organization owner.

The enterprise account must already exist. The skill checks prerequisites for your outcome. Unsupported APIs and work in an identity provider or another external system become explicit handoffs.

The skill does not administer GitHub Enterprise Server, deploy Azure infrastructure, or run the curriculum's lab provisioners. Use the hands-on sessions to learn a control or test the result with your team.

Preview. Packaging and offline workflow checks are tested. A controlled live setup journey is still required before production use.

A reviewed plan comes before writes

Plan saves the current assessment and proposed changes without changing GitHub. Read the plan, then request Apply when you want to execute it.

Each write batch needs approval. High-impact changes have a separate typed confirmation. The agent also asks before changing authentication. A general "proceed" starts the approval process; it does not approve a batch.

The skill verifies each completed operation and records what remains blocked or unverified. Resume rechecks identity and live state before continuing the known run.

Keep the private run directory outside source control. Legacy Bash wizard runs use a different format; keep them for reference and start a new skill plan.
