Before you start

You need macOS or Linux with Bash 3.2+, Git, GitHub CLI (gh), jq, and a SHA-256 utility. Use an existing enterprise and an account with permission for the changes you select. Some operations need an enterprise or organization owner.

Complete any required SSO and SCIM setup first. The wizard does not inspect or configure it.

Clone the repository, then authenticate to the intended host with your organization's credentials. Replace github.com with your enterprise's ghe.com host when needed.

git clone https://github.com/microsoft/frontier-agentic-devops-rvas.git
cd frontier-agentic-devops-rvas
gh auth login --hostname github.com
bash scripts/github-enterprise-wizard.sh init \
  --output "$HOME/github-setup.json"

The wizard never switches accounts. It checks the expected login before operating. Keep tokens in gh authentication or the runtime environment, never in configuration files.

The interview uses read-only GitHub lookups to suggest accounts and accessible resources. Saving your answers does not change GitHub settings.

The questions you will answer

The interview has six sections. Prompts depend on the packages you select and whether you create or adopt resources.

  1. Enterprise and account

    Which GitHub host and login will you use? Which enterprise owns the workspace? Does it use personal accounts or Enterprise Managed Users?

  2. Capabilities

    Which packages do you need? What should the default repository visibility be? Do you explicitly approve high-impact enterprise controls such as two-factor authentication or Codespaces constraints?

  3. Organization and project

    Create an organization or adopt one? Who are its owners? Define teams and repository access, then choose new or adopted repositories and their starter stack. New organizations also need a billing email.

  4. Capability settings

    Choose Actions permissions and approved actions. Selected packages add questions about Copilot recipients and features, CodeQL, Secret Protection, or Code Quality. Agentic workflows ask for an inference engine and whether to run live pilots. Other capabilities ask for owners and scope.

  5. Project conventions and review

    Choose repository labels and human review requirements. You can add Copilot instructions with actual build and test commands, or shared content in the private .github-private repository.

  6. Review and save

    Check the complete configuration summary. Fix invalid answers before saving. Saving writes your JSON configuration; it does not approve the plan.

Keyboard controls

Use Up/Down in menus and Space to toggle checkboxes. Enter or Right advances; B or Left goes back in menus. E opens the answer editor. Text fields accept :back, :edit, and :clear for an optional saved field.

Changing an earlier answer resets later choices that depend on it. Esc cancels from a menu; Ctrl+C stops anywhere. Cancelling before Save leaves the output file untouched.

Use init --plain --output "$HOME/github-setup.json" for scrollable text prompts, or add --no-discovery for an offline interview. Set NO_COLOR=1 to disable colors. Keyboard menus need at least 16 rows and 20 columns.

Check, review, and apply

bash scripts/github-enterprise-wizard.sh doctor \
  --config "$HOME/github-setup.json"
bash scripts/github-enterprise-wizard.sh plan \
  --config "$HOME/github-setup.json" --output "$HOME/github-plan.json"
less "$HOME/github-plan.json"
bash scripts/github-enterprise-wizard.sh apply \
  --plan "$HOME/github-plan.json" --run "$HOME/github-setup-run"

Read the complete plan, including proposed file contents and purchase recipients. Interactive apply asks for its exact digest. In CI, pass that digest through --approve. Regenerate the plan after changing the configuration or updating the wizard.

Approving the plan approves its selected purchases and live runs. They can incur costs. Licensing or external prerequisites without supported APIs remain manual handoffs.

Keep the configuration, plan, and run directory outside source control. The run stores the approved plan and a ledger; it can contain private configuration and reports.

Resume and verify

bash scripts/github-enterprise-wizard.sh status --run "$HOME/github-setup-run"
DIGEST="$(jq -r .digest "$HOME/github-plan.json")"
bash scripts/github-enterprise-wizard.sh resume \
  --run "$HOME/github-setup-run" --approve "$DIGEST"
bash scripts/github-enterprise-wizard.sh verify --run "$HOME/github-setup-run"

status shows action results. resume continues the approved run after you resolve blockers. verify reads settings and checks already-dispatched workflows; it does not purchase seats or start new runs.

Ready means the action's read-back or live check passed. Pending, unsupported, failed, or unverified actions still need work. An attested handoff records external evidence rather than API verification. Exit code 3 means the run is incomplete.

For manual handoff evidence and the full command reference, read the wizard's technical guide. Use the hands-on sessions when your team needs to learn or test the remaining work.
